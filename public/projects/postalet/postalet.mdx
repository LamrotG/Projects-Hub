# PostalET

## Overview

PostalET is a transparency-first postal code directory built specifically for Ethiopia.

Unlike many postal code websites that aggregate information without attribution, PostalET treats every postal code as a claim rather than an unquestionable fact. Every result is accompanied by its original source, a confidence rating, and a clear indication of what is known and what remains unverified.

The project was built around a simple philosophy:

> Transparency before certainty.

Instead of attempting to fabricate missing information or infer postal codes from nearby locations, the application explicitly communicates uncertainty to users.

---

# The Problem

Reliable Ethiopian postal code information is difficult to obtain.

Most existing websites:

* copy information from one another
* rarely identify where data originated
* provide no indication of confidence
* sometimes publish conflicting postal codes
* encourage users to trust information without evidence

For users filling government forms, shipping addresses, or international applications, this lack of transparency makes it difficult to know whether a postal code is trustworthy.

---

# Goals

The project was designed around several core goals:

* Build a centralized Ethiopian postal code directory.
* Prioritize transparency over completeness.
* Attribute every postal code to its source.
* Never fabricate or estimate missing data.
* Provide an accessible, responsive search experience.
* Improve discoverability through strong SEO practices.

---

# Solution

PostalET combines publicly available postal code references into a searchable directory while preserving the provenance of every postal code.

Each entry displays:

* the postal code
* its geographic location
* the originating data source
* a confidence rating
* supporting references when available

When a postal code cannot be verified, the application clearly communicates that no verified information exists rather than attempting to guess the result.

This approach allows users to make informed decisions based on the available evidence.

# Architecture

The application follows the Next.js App Router architecture.

The project separates responsibilities into distinct layers:

```
UI Components

↓

Search Interface

↓

Server/API Layer

↓

↓

```

Business logic is isolated within reusable library modules while presentation remains component-driven.

The folder structure emphasizes separation between routing, reusable UI components, and data access logic.

# Data Philosophy

A defining characteristic of PostalET is its data philosophy.

The application deliberately avoids assumptions.

It never:

* estimates postal codes
* derives codes from nearby locations
* generates placeholder values
* presents uncertain information as fact

Instead, missing information remains explicitly marked as unavailable until a trustworthy source can verify it.

This philosophy favors user trust over perceived completeness.

---

# Data Sources

PostalET references multiple publicly available datasets.

One source serves as the primary reference while additional sources provide supporting evidence where available.

Maintaining source attribution allows users to independently evaluate the reliability of the displayed information.

# Engineering Decisions

Several technical decisions shaped the project.

### Next.js App Router

The App Router enables server-rendered pages, improved SEO, and scalable routing for individual locations.

### Server Components

Server Components reduce unnecessary client-side JavaScript while improving performance.

### TypeScript

Strict typing helps maintain consistency across components, data models, and search functionality.

### Supabase

Supabase provides a managed PostgreSQL database while simplifying data access for search operations.

# Lessons Learned

Developing PostalET reinforced several engineering principles.

* Good software should communicate uncertainty instead of hiding it.
* Trust is built through transparency rather than appearance.
* Clear information architecture improves usability more than excessive visual design.
* Strong SEO begins with thoughtful application structure rather than after-the-fact optimization.
* Well-defined data models simplify future maintenance.

PostalET demonstrates how software can prioritize transparency over assumptions.
